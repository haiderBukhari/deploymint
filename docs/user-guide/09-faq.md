# FAQ / troubleshooting

**Does my code leave my machine?**
No. DeployMint runs entirely in your own Docker Compose stack. Your repo is
only ever read from the `./projects` mount. The only outbound network calls
are to whichever LLM provider you configured (for artifact generation and
chat) and, if you set them up, AWS Cost Explorer or a real cloud account via
Cloud Deploy.

**My project name changed when I registered it — why?**
Project names become Docker image tags and Kubernetes/Terraform resource
names, and those formats reject spaces and uppercase. `My App` becomes
`my-app` automatically. If your typed name is entirely punctuation with no
letters or numbers, registration is rejected outright with an explanation
rather than silently creating something broken.

**I didn't set an LLM API key — what happens?**
Artifact Smith falls back to a deterministic template instead of failing.
You still get a real, working, secure-by-default Dockerfile and Kubernetes
manifests — you'll see `generated by template` instead of `generated by llm`
on the run page, and a note in the run's "Notes" section explaining the
fallback (this is expected behavior, not an error — a run with this note can
still succeed).

**My run succeeded but nothing seems to be running anywhere.**
Check the Deployment & Evidence card on the run page — `mode: docker` means
it deployed via a plain `docker run` (no Kubernetes cluster was reachable),
and the card includes a clickable local URL. `mode: kubernetes` means it
went to a real cluster; check the pod name shown there with `kubectl`.

**My run failed with a blank terminal — what happened?**
Check the run's Errors section — a build that fails before producing any
output looks like an empty terminal, but the failure reason is always shown
there. A common cause is a Dockerfile issue caught before the build even
starts.

**How do I stop DeployMint from touching my cloud account?**
You don't need to do anything — DeployMint never touches real cloud
credentials unless you explicitly use the Cloud Deploy panel on a run's page
and enter them yourself for that one action. Generating Terraform is always
safe; running it is opt-in every time.

**Can I delete a project or a run?**
Projects: `DELETE /api/projects/{id}` via the API. There's currently no
delete button in the web dashboard.

**Where do the generated files actually live on disk?**
Under `.deploymint/<run_id>/` inside your project's own repo directory —
alongside your code, not in a separate DeployMint-managed location.
